## 2. Findings

### Q1. MCP status, November 2026

**Governance.** MCP became a founding project of the Agentic AI Foundation (AAIF), "a directed fund under the Linux Foundation," co-founded by Anthropic, Block and OpenAI with support from Google, Microsoft, AWS, Cloudflare and Bloomberg; founding projects were MCP, goose and AGENTS.md. "The Linux Foundation will not dictate the technical direction of MCP"; maintainer structure unchanged. At that time Anthropic cited "over 97 million monthly SDK downloads" and "10,000 active servers" [sourced: https://blog.modelcontextprotocol.io/posts/2025-12-09-mcp-joins-agentic-ai-foundation/, 2025-12-09].

**Spec maturity.** The 2026-07-28 spec revision moved MCP "from a bidirectional stateful protocol into a request/response stateless protocol" (initialize handshake and `Mcp-Session-Id` retired), deprecated Dynamic Client Registration in favor of CIMD, and reported "close to half-a-billion downloads a month" across Tier-1 SDKs with "both TypeScript and Python SDKs crossing the 1 billion total downloads threshold" [sourced: https://blog.modelcontextprotocol.io/posts/2026-07-28/, 2026-07-28]. Implication for a startup: a server written to the 2025 spec needs an auth/transport refresh; the protocol is still moving.

**Anthropic.** Custom remote-MCP connectors are available "on Claude, Cowork, and Claude Desktop for users on Free, Pro, Max, Ultra, Team, and Enterprise plans"; "Free users are limited to one custom connector"; connections originate from Anthropic's cloud "across every Claude client, including claude.ai, Claude Desktop, Cowork, and the mobile apps"; auth options are "Sign in now / Sign in when needed / No sign in", with header-based bearer tokens supported [sourced: https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp, page says "Updated this week" as of 2026-11-03]. Developer-facing docs add: a custom connector is added "by entering its URL, with no review by Anthropic"; Claude's client accepts "Text and image-based tool results"; it does not support resource subscriptions or sampling; limits are "~150,000 characters" per tool result and "240 seconds per tool call" on claude.ai/Desktop; Claude follows the 2025-03-26, 2025-06-18 and 2025-11-25 authorization specs and supports DCR [sourced: https://claude.com/docs/connectors/building, undated, fetched 2026-11-03]. Claude Code: `claude mcp add --transport http <name> <url>`; HTTP recommended, SSE deprecated, OAuth 2.0 supported [sourced: https://code.claude.com/docs/en/mcp, undated, references protocol revision 2026-07-28].

**OpenAI.** Official developer documentation (the Apps SDK has been re-organized as "Plugins"): a user adds a custom server at chatgpt.com/plugins — "Select the plus button, then Add custom MCP server", enter the URL "including the `/mcp` path", "Configure authentication, review the risk warning, and select I understand and want to continue", then "Create as a plugin"; "Account and workspace policies apply to adding and using custom MCP servers" [sourced: https://developers.openai.com/apps-sdk/deploy/connect-chatgpt and https://developers.openai.com/plugins/deploy/connect-chatgpt.md, undated, fetched 2026-11-03]. The quickstart says "This tutorial creates a personal plugin by connecting an MCP server" and "you will find the plugin in your personal Plugins directory and invoke its tool from ChatGPT Work on the web" ("switch the tab from Chat to Work") [sourced: https://developers.openai.com/plugins/quickstart.md, undated, fetched 2026-11-03]. Plugin guidelines: "Plugins must function reliably in ChatGPT on both desktop and mobile, including any UI components"; "Plugin extensions on the web are coming soon to ChatGPT Free and Go users" [sourced: https://developers.openai.com/plugins/llms-full.txt, undated, fetched 2026-11-03]. "ChatGPT currently requires manual confirmation in any conversation before write actions can be taken" [sourced: https://developers.openai.com/api/docs/mcp/, undated]. Secure MCP Tunnel was announced "for enterprise customers" on 2026-05-19 [sourced: https://developers.openai.com/api/docs/changelog, entry 2026-05-19].

Secondary vendor docs: Customer.io says "You must have a ChatGPT Pro, Plus, or Enterprise plan and enable Developer Mode in your ChatGPT account" and "You can't complete this process on the mobile app" [sourced: https://docs.customer.io/ai/mcp/chatgpt/, updated 2026-10-28; secondary]; Zuplo says Pro gets "read/fetch permissions in Developer Mode" and "full MCP support is not currently available to Pro users" [sourced: https://zuplo.com/docs/mcp-gateway/connect-clients/chatgpt.md, undated; secondary]. Community `savethepolarbears/google-photos-mcp` (56 stars, created 2025-04-16) "uses the Picker API because of the March 31, 2025 deprecation" [sourced: GitHub search API + README snippet, 2026-11-03]. This corroborates A1 from the BYO-AI side with a Google primary.

**Apple Photos ↔ Siri / third-party apps:** What Siri AI does with photos today (iOS 27 beta): "Search for a photo from years ago"; example prompt "Show me photos from the last time I went to Spain"; "draw on personal context understanding to search across messages, emails, photos, and more"; press-release screenshot "a search of photos from the previous weekend"; "Siri AI can take actions in apps like Messages, Music, Reminders, and more"; "get things done across apps with even more systemwide app actions" [sourced: https://www.apple.com/apple-intelligence/, fetched 2026-11-03; https://www.apple.com/newsroom/2026/06/apple-unveils-next-generation-of-apple-intelligence-siri-ai-and-more/, 2026-06-08]. Photos app itself gets Clean Up, Extend and Spatial Reframing [sourced: https://9to5mac.com/2026/06/08/new-siri-whats-new/, 2026-06-08; secondary]. Apple's `.photos` app-schema domain lets a third-party photo app expose entities `asset`, `album`, `recognizedPerson` and 28 intent schemas (addAssetsToAlbum, cleanupPhoto, copyEdits, createAlbum, createAssets, crop, deleteAlbum, deleteAssets, duplicateAssets, editAsset, openAlbum, openAsset, pasteEdits, postToSharedAlbum, removeAssetsFromAlbum, setDepth/Exposure/Filter/Rotation/Saturation/Warmth, straighten, toggleDepth, toggleSuggestedEdits, updateAlbum, updateAsset, updateRecognizedPerson, search); **two are flagged deprecated: `search` and `openAsset`** [sourced: https://developer.apple.com/tutorials/data/documentation/appintents/app-schema-domain-photos.json, fetched 2026-11-03]. The sample "Integrating your photo app with Apple Intelligence" (availability iOS/iPadOS/macOS 27.0+) shows the content-discovery path: conform `AssetEntity` to `IndexedEntity`, donate to Spotlight, "enable semantic search results"; conform to `Transferable` so "the system can pass the sample app's content to other apps" [sourced: https://developer.apple.com/documentation/appintents/integrating-your-photo-app-with-apple-intelligence, © 2026]. WWDC26 session 240: "Siri can now access your app's entities, the real meaningful content inside your app"; for data that "lives on a server, or changes too frequently to index ahead of time ... you can use EntityStringQuery ... **Answer to "could OUR app be the Siri-queryable store?"** Partially yes, on paper: a third-party app can (a) index its photo entities into Spotlight for Apple's semantic search, (b) answer Siri's free-text requests via `EntityStringQuery` with its own server-side search, and (c) expose edit/album actions via schemas. Caveats: Apple's semantic index is over the metadata/representation you donate, not your embeddings; the dedicated `search` and `openAsset` schemas are deprecated; Siri AI is beta, six languages, not in the EU on iOS, with daily limits; and whether Siri will prefer Apple Photos over a third-party library for "show me photos of X" is [unknown: no Apple statement found].

### Q6. Semantic-search quality bar; what Immich / Ente / PhotoPrism deliver

- **User expectation evidence (Google Ask Photos backlash):** Reddit thread "Did Gemini ruin search in Photos?" drew "dozens of responses"; failing queries were text-in-photo ("I used to be able to search a word or phrase in my photos and then click to find photos with that text in it") and simple object queries ("a monkey at a zoo"); Google PM Jamie Aspinall: "Ask Photos isn't where it needs to be, in terms of latency, quality and ux"; a classic-search toggle was added [sourced: https://www.androidpolice.com/google-photos-users-are-ditching-ask-photos-after-gemini-broke-their-search/, 2026-05-31; secondary]. Implication: the bar is "at least as good as classic keyword/OCR/face search, instantly".
- **Immich:** contextual search via CLIP in Postgres/VectorChord; model switchable; multilingual model families `nllb`, `xlm`, `siglip2` available; "The tradeoff of using these models is that they're slower and/or use more memory" [sourced: https://docs.immich.app/features/searching, last updated 2026-10-21]. Maintainer benchmark (text→image recall, fp32, i9-12900H): default `ViT-B-32__openai` XTD-en 73.9 / XTD-mean 21.2 / XM-en 56.9 / XM-mean 8.4, 1.6 GB RSS; `ViT-B-16-SigLIP2__webli` 89.2 / 77.4 / 74.3 / 49.5, 3.3 GB; `ViT-SO400M-16-SigLIP2-384` 90.1 / 81.9 / 73.9 / 55.2, 9.1 GB; EmbeddingGemma-2@140 90.4 / 85.8 / 76.9 / 70.9, 3.0 GB but ~1,580 ms/image [sourced: https://github.com/immich-app/immich/discussions/32173, 2026-10-06..08]. Complaint pattern: the discussion's opener says "the good multilingual models are effectively locked to a decent server" and "the model tables effectively assume a server with headroom" (Shrijayan, 2026-10-06), to which maintainer bo0tzz replied that the "small hardware" claims "don't hold up for me" (2026-10-07) [sourced: same discussion]; separately, issue #32488 (2026-10-16) reports switching models "because Chinese text search was unusable with the English-only default" and a locale-tag bug that silently falls back to English [sourced: https://github.com/immich-app/immich/issues/32488, 2026-10-16].
- **Ente:** on-device only; magic search uses Apple MobileCLIP; faces via YOLO5Face (small) + MobileFaceNet; ONNX Runtime; indexes encrypted before upload; "The only difference between platforms is the time it takes to index" [sourced: https://ente.com/ml/, undated]. Whether ML runs in the web client is [unknown: neither ente.com/ml nor ente.com/help/photos/features/machine-learning states platform coverage]. User complaints (GitHub, ente-io/ente): "Magic search is inconsistent" (#5410, open, 2025-03-22); "High CPU usage during inference for Magic search" (#645, closed, 2024-12-27, 11 comments); "Search has stopped working in the Ente Photos desktop app" (#11231, closed, 2026-07-06); "Crashes a lot if magic search is enabled" (#3290, closed, 2026-05-29); discussions "Magic Search OCR Doesn't Work for Non-English Languages" (2025-04-03, unanswered), "Inconsistency across platforms in search" (2024-12-11), "[Photos] Headless Linux/server ML indexing for face recognition and magic search" (2026-05-21), "Magic Search on Mobile" (2024-09-18) [sourced: https://github.com/ente-io/ente/issues?q=is%3Aissue+magic+search and /discussions?discussions_q=magic+search, fetched 2026-11-03]. No official Ente MCP; unofficial `aminamos/ente-mcp` has 0 stars (created 2026-09-03) [sourced: GitHub search API, 2026-11-03]. Ente's E2EE design means a server-side MCP would have to run on-device or break the threat model — a structural reason Ente is unlikely to offer BYO-AI cloud-side, and the headless-indexing request above shows users feel that constraint.
- **PhotoPrism:** ships MCP natively — streamable HTTP at `/api/v1/mcp` plus `photoprism mcp serve` stdio; library tools let a client "search and browse the library with the permissions of the signed-in account", read-only; OAuth with `WWW-Authenticate` protected-resource metadata; `search_media` returns "at most 50" items per call; per-account `--mcp=false` disable flag [sourced: https://docs.photoprism.app/developer-guide/api/mcp/, undated, © 2018-2026]. Search quality: PhotoPrism's search is label/classifier based — the user guide's only description is "Shows your photos and videos grouped by labels like cat, dog or beach" with no mention of CLIP or natural language [sourced: https://docs.photoprism.app/user-guide/search/, undated]. Complaints: "Labels: Allow a model to be trained for better results" open since 2020-08-07 with 75 reactions — "The current model is not really good. ## 3. Seed assumptions tested

**A6 — "Major assistants will let users attach a private corpus as a tool with low friction."** Status: **PARTIAL (holds for Claude; unproven-to-broken for the mass market).**
- Holds: Claude — Free tier, every client including mobile, no-auth or bearer allowed, no review [sourced: support.claude.com 11175166; claude.com/docs/connectors/building].
- Unproven: ChatGPT — the official path exists (chatgpt.com/plugins > "Add custom MCP server" > personal plugin, used in "Work" chats on the web) [sourced: developers.openai.com plugins docs], but which consumer plans may use it is [unknown: no fetchable OpenAI page says; secondaries say paid-only, web-only setup, Pro read-only]. The EEA/UK/CH exclusion is [unknown: snippet-only].
- Partial: Gemini — custom apps require 18+, US, English, personal account, web setup; no tier stated; then usable on mobile [sourced: support.google.com 17209137]. Spark's custom MCP is AI Ultra beta [sourced: blog.google 2026-05-19, 2026-06-30].
- Broken: Microsoft consumer Copilot — no path [sourced: support.microsoft.com]. Apple — no MCP in any primary through the June 2026 App Intents updates; the native path is App Intents, which exposes actions and Spotlight-indexed entities, not an arbitrary tool endpoint, and the photos `search`/`openAsset` schemas are deprecated [sourced: developer.apple.com JSON docs, fetched 2026-11-03].
- Trend: Claude opened custom connectors to Free (support page, current); Gemini's custom-app support page and Spark custom MCP both date from 2026 [sourced: blog.google 2026-06-30]; OpenAI says plugin extensions are "coming soon to ChatGPT Free and Go users" [sourced: developers.openai.com plugins docs]. Direction is toward more access, but "low friction" today is verified only inside Claude. For a consumer product the realistic 2026 funnel is: install our app, open Claude, paste URL. Everyone else needs a desktop browser and, per the only dated sources, probably a paid plan.

**A1 (cross-check from this track)** — Google removed third-party library read access 2025-03-31: confirmed by Google's own API notice ("scopes will be removed", "403 PERMISSION_DENIED after March 31, 2025", "only ... media items that were created by your app") [sourced: developers.google.com/photos/support/updates] and corroborated by the absence of any ChatGPT Photos connector and by community MCP servers falling back to the Picker API. Holds.

**A4 (cross-check)** — "Apple/Google will not ship open AI access themselves": Google exposes Photos to Gemini (its own AI, one of 86 connected apps [sourced: support.google.com/gemini/table/17434654, fetched 2026-11-03]) with rich search and Spark agentic actions, but not to third-party AIs; Apple exposes third-party apps *to Siri* but not Apple Photos *to third-party AIs*. Partial: the walled gardens open inward only. That is the only durable gap a BYO-AI product fills, and it is a gap only for users who want a non-Google/non-Apple assistant over Google/Apple photos.

**Wedge or feature?** Evidence says **feature**. (1) The MCP endpoint is commoditized: 54,763 active registry servers [sourced: registry API, 2026-11-03]; 28 Immich MCP repos [sourced: GitHub, 2026-11-03]; PhotoPrism built-in; Obsidian vaults reached 4,515-star community MCPs with no vendor involvement. (2) The one consumer company that tried "your corpus as a tool, subscription, many clients" — Khoj — shut its cloud and named both that architecture and "challenges in defensibility with all the big labs coming out with similar products" as reasons [sourced: app.khoj.dev, 2026-04-15]. (3) Reach: the two assistants with published nine-figure user counts — ChatGPT "More than 800 million people use ChatGPT every week" [sourced: https://techcrunch.com/2025/10/06/sam-altman-says-chatgpt-has-hit-800m-weekly-active-users/, 2025-10-06; secondary quoting Altman] and Gemini "more than 900 million people ... every month" [sourced: blog.google, 2026-05-19] — are the ones where custom-MCP access is gated or undocumented; the assistant with the frictionless path, Claude, publishes no consumer user count [unknown: Anthropic publishes no MAU; none found]. The conditional conclusion: BYO-AI's frictionless addressable audience is bounded by Claude's consumer base, whatever its size, until OpenAI or Google document a free-tier path. (4) The quality bar is set by Ask Photos' failure — users punish semantic search that is slower or worse than keyword/OCR — and by PhotoPrism's experience that an MCP over a weak label index is still a weak search. The index is the product; the MCP server is a two-day wrapper on top. Position BYO-AI as a checkbox on the archive product, not as the reason to buy.
